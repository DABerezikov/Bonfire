# Ввод семян и редактируемые подборы

## Этап 1 — полная библиотека и операции хранения (завершён)

- `ISeedEditorOptionsReader` возвращает независимый полный каталог культур, сортов,
  производителей и связей сорт → культуры. Пять скалярных проекций без EF-графов
  и JOIN, независимо от числа пакетов. Отсутствие каталога в старом DTO явно через Option.
- Добавление пакета переиспользует библиотечные записи даже при отсутствии пакетов.
  Точное сопоставление имён, прежнее пополнение по году и семантика общего производителя
  сохранены. Характеристики существующего сорта не теряются.
- `ManageSortOptions` → `SortOptionName` → `DbSortOptionStore`: цвета и сроки созревания
  объединяются из SortOptions и фактических характеристик сортов. Сравнение имён
  без учёта регистра и крайних пробелов. Добавление дубликата и переименование
  в занятое имя запрещены. Переименование обновляет все связанные сорта одним SaveChanges.
- Удаление используемого цвета/срока запрещено. Удаление культуры, сорта и производителя
  проходит через DeleteLibraryEntry: свежая проверка связей, включая профили,
  региональные сроки, партии, многолетники и журнал. Неиспользуемое значение можно удалить.
- Схема БД не меняется. Ожидаемые отказы — Result; технические ошибки БД
  перехватываются только в адаптере хранения.
- Проверки: SQLite добавление/переименование/удаление, сохранение связей и характеристик,
  полный каталог без пакетов. Новая проверка добавления из полной библиотеки выявила
  создание дубликатов до исправления ResolvePlantAsync.

## Этап 2 — интерфейс и фильтры (завершён)

- Общий WPF-подбор для всех редактируемых ComboBox: независимый список совпадений,
  сохранение исходного текста, каретки, привязки и свободного ввода.
- Класс ограничивает культуры, сорта и производителей; культура подставляет класс
  и ограничивает потомков; сорт ограничивает производителей; производитель не меняет предков.
  Одноимённый сорт у нескольких производителей допускает все соответствующие варианты.
  Новая культура/сорт допускает всех производителей. Несовместимый прежний выбор
  очищается с подсказкой. Редактор библиотек всегда видит полный каталог.
- Вкладка цветов и сроков созревания: добавить, переименовать, удалить, обновить.
  Маркер обязательности, ошибка и доступность сохранения используют одно правило.
- Заголовок культуры и сорта выделяется и копируется; подпись даты — «Дата поступления».
- Неограниченные многострочные редакторы получают прокрутку и ограниченную высоту;
  описание сорта не сдвигает кнопки сохранения и удаления.
- Проверки: фильтры, сброс несовместимых значений, WPF ввод «с» и произвольного слова,
  сохранение привязки, копируемый заголовок и описание 30 000 символов.

## Исправление пустого выбора — 03.11.2026

В форме добавления сорта и производители явно отключают
IsSynchronizedWithCurrentItem: первый элемент ICollectionView не является
пользовательским выбором. Поля остаются пустыми при открытии, очистке и обновлении
каталога. Обновление подборов от CollectionChanged откладывается до завершения
текущего выбора WPF (DispatcherPriority.DataBind), чтобы не восстанавливать прежний
пустой текст поверх выбранного значения. Изменения самого адаптера не планируют
повторную перестройку.

WPF-регрессия сначала воспроизвела неявный выбор «18 дней», затем проверила пустое
состояние, фильтрацию по культуре, явный выбор сорта/производителя, очистку и refresh.
Проект ViewModels: 374/374. Общий гейт после исправления: 1837/1837.

## Подсказки без повторов — 03.11.2026

Текстовый подбор объединяет одинаковые отображаемые названия без учёта регистра
после применения CollectionViewSource-фильтра. Полный каталог и ID сохраняются:
списки редактора библиотек не сокращаются, записи БД не объединяются.
ComboBox с привязкой SelectedItem/SelectedValue выбирает конкретную сущность;
такие варианты не объединяются по одной надписи.

Сорта фильтруются по всем ID одноимённой культуры в выбранном классе. Проверка
совместимости производителя учитывает все записи с тем же именем. Выбор не
сбрасывается из-за несовпадения ID первой одноимённой записи.

Привязки HorizontalContentAlignment/VerticalContentAlignment контейнера ComboBoxItem
ссылаются явно на свой ComboBox. Поиск ItemsControl-предка в отсоединённых контейнерах
при перестройке списка не требуется.

WPF-регрессии: три одинаковые надписи → одна подсказка; фильтр, оставляющий только
третью запись, сохраняет её ID; каталог не сокращается; выбор конкретных сущностей
с одинаковой надписью не теряет варианты; диагностический журнал не содержит
Cannot find source, обе привязки выравнивания имеют явный Source.
Проверки ViewModels: 385/385. Общий гейт: 1858/1858.

## Пробелы и оставшиеся контейнеры ComboBox — 03.11.2026

Уточнение владельца: свободные пробелы исключаются при сохранении названий.
LibraryName.Create теперь использует единую NormalizeWhitespace: убирает края,
схлопывает последовательности Unicode-пробелов (включая NBSP и табуляцию) в один
обычный пробел, сохраняя регистр и буквы. Правило применяется к именам справочников,
сортам и необязательным значениям цвета/созревания. Описания и примечания не меняются;
None и Some("") сохраняют различие.

SeedAcquisition использует проверенные нормализованные имена. Writer ищет свежие
существующие записи с учётом исторических пробелов и пополняет имеющийся пакет,
а не создаёт новый. Названия затронутых записей нормализуются при записи.
DbLibraryNameLookup выполняет поиск по имени и проверенному каноническому ключу;
данные кэша UI не используются для принятия решения. Автоматического объединения
разных ID и массовой очистки БД нет. Разработка и проверки выполнялись на фикстурах;
файл рабочей БД использовался только для чтения диагностического примера.

В старом файле подтверждены `Малопа` и `Малопа ` с U+0020. Подбор и его фильтры
используют тот же ключ нормализации; исходные записи/ID сохраняются. Отдельный тест
упражняет восемь циклов выбора, открытия, фильтрации и восстановления списка.

## Сброс производителя при смене класса — 04.11.2026

При явном изменении класса производитель очищается независимо от совместимости
с новым классом и наличия имени в справочнике. Повторное присваивание того же
класса ничего не сбрасывает. В режиме «Собрано» сохраняется автоматическое
значение «Свои семена»; автоматическое определение класса по культуре использует
прежнюю проверку совместимости. Подсказка о сбросе зависимых полей обобщена.

Четыре новые проверки охватывают общего/нового производителя и класс с культурами/
без культур. Две существующие WPF-регрессии дополнены проверкой очистки производителя
в VM и ComboBox при быстром и завершённом выборе. Затронутый набор: 40/40.
