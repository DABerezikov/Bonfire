## 24.10.2026 — Application и явное отсутствие в посеве

Первый этап закоммичен как `9f346ff`; pre-commit подтвердил 665 тестов.
Следующий перенос завершает границу операции посева из этапа 2 плана.

### Фактическая архитектура

`SeedlingsViewModel → ISeedlingsService → ISowSeeds/SowSeeds → SeedStock.Sow`.
Application использует `ISowingSessionFactory/ISowingSession` для чтения и сохранения,
`ILunarCalendar` — для вычисления фазы. Порты определены в Application;
`DbSowingSessionFactory` реализован в BonfireDB, `MoonPhaseCalendar` — в WPF-проекте
как адаптер существующей библиотеки. Регистрации добавлены в прежние DI-регистраторы.

`Bonfire.Application` ссылается только на Domain. BonfireDB ссылается на Application
для реализации его порта. Проверки зависимостей защищают Domain/Application от EF,
WPF и DI. Из-за нового пространства имён ссылки на WPF `Application` уточнены явно.

### Контракты и эффекты

- Общий `Option<T>` имеет закрытые sealed-варианты `Some/None`. `Some(null)` запрещён.
  Полиморфный `Map` реализован отдельным extension с pattern matching; `Match`
  обрабатывает присутствие и отсутствие без nullable-accessors.
- `SowingRequest` перенесён из WPF в Application; место посадки — `Option<string>`.
  Пустой/пробельный текст нормализуется в `None`, сохраняя прежнюю семантику.
- `SowingReceipt` больше не содержит `Seed`/`Seedling`. Он возвращает значения посева,
  метаданные, ID сохранённой партии и актуальные остатки. Вес представлен `Option<double>`:
  `None` сохраняет неизвестность, `Some(0)` — известный нулевой остаток.
- Одна сессия владеет одним UnitOfWork: чтение свежего пакета, доменный расчёт, запись
  партии/метаданных и остатка одним SaveChanges. Освобождение гарантировано через
  `await using` при успехе, отказе, исключении и отмене.
- Application принимает CancellationToken и передаёт его порту; EF-адаптер передаёт
  токен чтению и сохранению. Программные/инфраструктурные исключения сохраняют
  прежний путь обработки; ожидаемые отказы возвращаются через Result.
- Прежний UI после успеха очищает редактор и обновляет остатки, затем получает партию
  через существующий запрос чтения. Если партия уже отсутствует, показывает, что
  посев сохранён, и предлагает обновить список; редактор не допускает повторную отправку.

## 24.10.2026 — жизненный цикл DI и асинхронный startup

Выполнен запланированный на 21:30 этап 3, база `625c7ec`.

### Изменения и порядок выполнения

- `DbInitializer` стал scoped. Инициализация разрешается из `CreateAsyncScope`,
  область освобождается после завершения миграций. CancellationToken передаётся
  миграциям, чтению и сохранению метаданных.
- `Program.CreateHostBuilder` — единый путь построения host для приложения и тестов:
  общий ConfigureServices, JSON из каталога исполняемой сборки, ValidateScopes и
  ValidateOnBuild. Путь к самой БД не менялся.
- `ApplicationLifetime` координирует однократные async Start/Stop/Dispose. Сначала
  завершается инициализация БД, затем запускается host. Остановка отменяет незавершённый
  startup, ожидает его и StopAsync; ресурсы освобождаются даже при ошибке остановки.
  Для host с IAsyncDisposable ожидается асинхронное освобождение.
- Из App.xaml удалён StartupUri: MainWindow создаётся и показывается только после
  успешного startup. На время запуска действует OnExplicitShutdown, затем —
  OnMainWindowClose. Ошибка запуска очищает ресурсы и завершает приложение с кодом 1.
- `WindowShutdown` уважает отмену закрытия из проверки несохранённых правок,
  блокирует повторные запросы и ожидает очистку до окончательного Close. Окно на
  время остановки отключается. После завершения проверки подтверждение повторно
  не запрашивается. Финальный Close отложен через Dispatcher-контекст.
- Убран async void OnExit. Подписки глобальных ошибок снимаются, предыдущий обработчик
  команд восстанавливается. Обычное закрытие завершает host до выхода из Dispatcher;
  Program содержит резервное ожидание очистки после возврата из Run на границе
  процесса. Этот синхронный мост не выполняется внутри UI/startup. Код Run передаётся
  в Environment.ExitCode.

## 25.10.2026 — удаление самостоятельной рассады с явным выбором

Владелец уточнил: семена и рассада связаны информационно. После посева рассада

причине без возврата. Отмена не меняет данные. Если источник отсутствует, возврат

повторный запрос, отсутствие источника и откат БД → общий тест-гейт. Сохраняем
исходные Quantity/Weight, общие растения и существующие каскады; сбор семян из
урожая не является возвратом и в этот срез не входит.
