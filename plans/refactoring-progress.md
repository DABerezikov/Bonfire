# Реализация рефакторинга

## 24.10.2026 — функциональное ядро посева и независимый черновик

Основание: [актуальный план](refactoring-functional-domain.md).
Составлена [карта контрактов](domain-contracts.md) по текущему коду и схеме.

### Изменения

- Выделен `Bonfire.Domain` (`net10.0`) без пакетов и ссылок на WPF, EF или DI.
  Архитектурная проверка контролирует зависимости сборки.
- Существующий `Result` перенесён из BonfireDB в `Domain/Functional`, потребители
  переведены на новое пространство имён. Внутреннее состояние представлено закрытыми
  вариантами успеха/отказа; устранены внутренние `!`. Успех с `null` запрещён;
  `From(null)` возвращает явный отказ.
- `SeedAmount` — проверенное иммутабельное значение с единицей. `SeedStock.Sow`
  возвращает новый остаток и расход, не меняя исходную модель. Проверяются конечность,
  положительный расход, совпадение единиц и доступность остатка.
- `SeedlingsService.SowAsync` загружает актуальный пакет, вызывает доменную операцию,
  сохраняет расход и новую партию одним `SaveChanges` в общем UnitOfWork.
- Команда UI передаёт запрос и обновляет коллекции/кэш только после успешного
  результата. При ожидаемом отказе показывает причину и сохраняет введённые данные.
- `SeedlingMapper` независимо копирует всходы, пересадки и обработки с обратными
  ссылками на копии. Сохраняются метаданные партии и идентификаторы.
- Схема БД, миграции и XAML не менялись.

### TDD и итоговая проверка

Red до реализации подтверждён:

| Граница | Падающие проверки | Причина |
|---|---:|---|
| Черновик | 2 | Общие вложенные объекты и потерянные метаданные |
| Доменный посев | 4 | Операция ещё не вычисляла новое состояние |
| SQLite-посев | 4 | Атомарная операция ещё не была реализована |
| UI-посев | 3 | Использовались старые вызовы с предварительным изменением кэша |
| Result | 2 | Допускался успешный результат без значения |

После Green проверены штуки/граммы, сохранение метаданных, отсутствие дублирования
растения, устаревший запрос, отсутствующий пакет/вес, неверные единицы/дата/источник,
нулевые/отрицательные/нечисловые количества, независимость черновика и ожидание UI.
SQLite-триггер принудительно отклоняет изменение остатка: новая партия и её записи
также не сохраняются, исходный остаток остаётся прежним.

Общий гейт: `dotnet test Bonfire.sln --no-restore --nologo -v q -m:1 -nr:false -p:UseSharedCompilation=false --logger trx --results-directory artifacts/refactoring-stage-1`.
Итог: **665/665**, без пропусков; добавлено 32 проверки относительно базы 633.
TRX находятся в игнорируемом `artifacts/refactoring-stage-1/`.
Существующие предупреждения NuGet о зависимостях не исправлялись этим этапом.

### Оставшиеся границы

- Application ещё не выделен: оркестрация временно находится в существующем сервисе,
  `SowingReceipt` содержит EF-модели для прежнего UI. Следующий перенос должен убрать
  эту зависимость, сохранив проверенный сценарий.
- Nullable-accessors `Result.Value/Error` оставлены для неперенесённых потребителей;
  новые операции используют `Match/Bind`. Переход остальных сценариев на `Option`
  ещё не выполнен. Nullable EF/WPF-модели не объявляются доменными контрактами.
- `double` для штук сохранён ради совместимости; переход на целое количество требует
  отдельного решения. Одновременная запись из нескольких процессов не проверена:
  атомарность одного сохранения не заменяет контроль конкуренции.
- Исправление DI/startup, остальные доменные агрегаты, разделение ViewModel и внешних
  интеграций остаются следующими этапами. Визуальные изменения не выполнялись;
  полноценный запуск и системные диалоги не объявляются проверенными.
- Отчёт покрытия `Tests/COVERAGE.md` относится к исходной базе; новый процент не измерялся.
