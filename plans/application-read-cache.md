# Кэш чтения и навигация без повторных запросов

Согласовано 03.11.2026: фильтрация списков выполняется в памяти через существующие
CollectionViewSource; переключение вкладок не является причиной чтения БД.

## Этап 1 — общий кэш снимков (завершён)

IReadModelCache/ReadModelCache в Application сохраняет только успешные Result
с независимыми immutable DTO. Ключ включает тип результата, область зависимостей
и параметры запроса. Параллельные чтения одного ключа разделяют одну операцию.
Отмена одного ожидающего не отменяет общий запрос. Failure, отменённые и аварийно
завершённые операции не остаются успешным снимком. Изменение версии во время чтения
не позволяет вернуть устаревший результат: чтение повторяется для новой версии.

Области: остатки семян, каталог, пользовательские варианты цвета/созревания,
рассада, огород, сезонные планы, регионы/агропрофили, журнал сборов, многолетники.
Зависимости запросов явно задаются масками этих областей.

UnitOfWork определяет затронутые области по изменённым EF-строкам и владельцам
owned-значений. Только успешный SaveChanges с изменениями инвалидирует соответствующие
снимки. Следующее необходимое чтение получает свежий снимок и сохраняет его в кэше.
Ошибка записи, отмена и отказ валидации кэш не сбрасывают.

Поток:

    UI.read(key) → cache.success ? snapshot : reader → Result
    action → Domain → writer с чтением свежего состояния → SaveChanges
    success → invalidate(affected areas)
    next read → fresh reader → cached snapshot

Кэш подключён к фасадам чтения семян, рассады, библиотек, огорода, планирования,
журнала и многолетников. Расчёт плановой партии, сохранение и выгрузка списка покупки
продолжают пользоваться свежими портами; остаток для записи не берётся из кэша UI.
Кэш ограничен сессией приложения. Изменение SQLite внешним процессом не является
действием приложения; для него требуется явное обновление или перезапуск.

Доказательства: 4 теста поведения кэша и 6 SQLite-тестов. SQL-журнал подтверждает
ноль запросов при повторном чтении, актуализацию после посева/переименования/удаления,
защиту кэша после неудачного коммита и актуализацию owned-характеристик. Добавление
неиспользуемого цвета обновляет только варианты, сохраняя снимок инвентаря.

## Этап 2 — жизненный цикл вкладок (проверки продолжаются)

- Семена отдельно отслеживают версии инвентаря и вариантов редактора.
- Рассада отслеживает версии собственных партий и доступных семян.
- Планирование, справочники, журнал и многолетники загружают данные при изменении
  соответствующей версии; Loaded вызывает EnsureLoadedCommand.
- Огород сохраняет загруженные планы и обновляет пикеры при изменении семян/рассады.
- Неизменившиеся коллекции и выбор не пересоздаются при навигации. Ошибка загрузки
  не помечает область загруженной; следующий вход повторяет попытку.
- Явные кнопки «Обновить» инвалидируют свой набор чтения и запрашивают свежие данные.
- Поиск и фильтры не меняют версии и не создают запросы к БД.

Промежуточный гейт рабочего дерева: **1852/1852** (Models 843, Services 589,
ViewModels 379, Repository 35, SeedsFromViewModel 6). Проверки реальной навигации
со счётчиком SQL и финальный startup/exit выполняются на следующем этапе.
