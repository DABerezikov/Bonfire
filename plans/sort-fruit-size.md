# Размер плода и информационные панели сорта

Размер плода задаётся в сантиметрах двумя необязательными целыми значениями
`MinFruitSize` / `MaxFruitSize`. Ноль допустим; отрицательные значения и минимум
больше максимума дают отказ. Допустимы обе отсутствующие границы и одна граница.
Только минимум отображается как «от …», только максимум — «до …», пара — «… - …».

Поток: `SeedDetailsEditor → SortEditModel → SeedEditMapper → EditSeed →
SortCharacteristicsValues / SortCharacteristics → SortCharacteristicsDbMapper →
PlantSort`. Существующий writer сохраняет характеристики общего сорта вместе
с пакетом одним SaveChanges. Обратное чтение использует тот же DB-маппер;
`LibraryMapper` восстанавливает независимый черновик. В Domain значения представлены
через `Option<int>`, в EF — `int?`. Дробный и нечисловой ввод отклоняется WPF-правилом
до преобразования, ошибка отображается в tooltip и блокирует сохранение.

Миграция `20261031144321_AddFruitSize` добавляет два nullable INTEGER-столбца
в `PlantsSort`. Старые записи получают NULL, другие поля и связи сохраняются.
Рабочая БД в ходе разработки не обновляется; штатный DbInitializer применяет
миграцию при запуске новой сборки. Down удаляет только два новых столбца:
перед откатом заполненные размеры нужно сохранить отдельно, если они нужны.

`SortInformationPanel` используется в семенах и рассаде. Строка без обеих границ
или без одиночного текста скрывается целиком. Пустая строка и отсутствие значения
не занимают высоту; ноль остаётся видимым. Описание без текста скрывается вместе
с подписью и рамкой. Сетка характеристик независима от высоты описания.

Проверки: Domain/WPF-валидация диапазона и целочисленного ввода; запись/чтение/
очистка обеих границ через SQLite; обновление старой схемы, сохранение старых
полей и откат/повторное применение миграции; WPF-текст, BindingStatus, скрытие
пустых строк без промежутков, отображение нулей, снимки семян/рассады при 96/144 DPI.
