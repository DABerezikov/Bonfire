# Исходный план глубокого рефакторинга Bonfire

Статус: исходное предложение; уточнено в [актуальном плане](refactoring-functional-domain.md).
База: `8a51f5f`, 633 успешных теста, покрытие строк runtime C# — 88,1%.
Полный запуск, нативные диалоги и визуальная проверка разных DPI остаются отдельными границами.

## Подтверждённые проблемы

- `GardenPlanViewModel` (1172 строки), `SeedlingsViewModel` (906) и `SeedsViewModel`
  (716) объединяют состояние экрана, преобразования и бизнес-операции.
- EF-сущности доходят до UI; сохранение отсоединённых графов может менять связанные данные.
- Создание рассады и списание семян выполняются отдельными сохранениями.
- `SeedlingMapper.CopyInto` разделяет коллекцию всходов с исходной записью.
- Singleton `DbInitializer` получает scoped-контекст; startup использует `.Wait()`.
- Экспорт Excel объединяет создание документа, диалоги и системные действия.

## Целевые слои

| Проект | Ответственность |
|---|---|
| `Bonfire.Domain` | Правила учёта, количества, единицы и состояния без WPF/EF |
| `Bonfire.Application` | Операции пользователя, запросы, результаты и порты внешних зависимостей |
| `BonfireDB` | EF, SQLite, миграции и сохранение |
| `Bonfire.Infrastructure` | Excel, файлы и внешние интеграции |
| `Bonfire` | WPF, ViewModel, редакторы, навигация и сборка зависимостей |
| `MoonCalendar` | Существующая библиотека расчётов |

Новые проекты заполняются по мере переноса сценариев. Границы закрепляются ссылками
проектов и архитектурными тестами.

## Последовательность

1. **Контракты.** Описать владельцев свойств культуры, растения, сорта, производителя,
   пакета, рассады и посадки; разделить сохраняемое поведение и исправления.
2. **Целостность.** Сделать посев атомарным, изолировать черновики, проверить отказ
   сохранения. Использовать атомарный `PlantingService` как отправную точку.
3. **Запуск.** Упорядочить конфигурацию, DI, области жизни, обработчики ошибок,
   запуск и завершение; убрать блокирующее ожидание.
4. **Операции.** Переносить сценарии в Application: семена и библиотеки → рассада →
   посадки и план огорода. Последовательно применять существующий `Result`.
5. **Домен.** Выделить подтверждённые правила и value objects, сохранить полиморфные
   состояния, Composite теплицы и DB-дискриминаторы.
6. **Представление.** Разделить редакторы, фильтры и выбор источника; у планировщика —
   управление планом, выделение, масштаб, геометрию и размещение. Заменять EF-графы
   моделями чтения и независимыми черновиками.
7. **Интеграции и очистка.** Разделить генерацию Excel, выбор пути и открытие файла;
   удалить устаревшие API и повторный маппинг, уточнить загрузку данных и документацию.

## Проверки и порядок работы

Каждый этап оставляет работающее приложение и завершается отдельным коммитом.
Исправления и новое поведение: Red → Green → Refactor. Характеристические тесты
сохраняют наблюдаемое поведение при изменении внутренних классов.

Общий гейт — все пять проектов через `dotnet test Bonfire.sln`. Изменения UI требуют
визуальной проверки; изменения хранения — SQLite-интеграций и проверки отказов.
Миграции схемы выполняются отдельно с доказательствами сохранности данных.
