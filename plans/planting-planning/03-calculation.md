## Математика и значение результата

Все интервалы включительные. T — вручную заданная высадка, G — прорастание,
A — допустимый возраст от всходов. S — дата посева.

```text
Возможное окно посева:
    Smin = Tmin − Gmax − Amax
    Smax = Tmax − Gmin − Amin

Окно, позволяющее подобрать высадку внутри T при каждом G из диапазона:
    Rmin = Tmin − Gmin − Amax
    Rmax = Tmax − Gmax − Amin
    если Rmin > Rmax, это окно отсутствует

Для выбранного S и предполагаемого g:
    всходы E = S + g
    высадка по возрасту = [E + Amin, E + Amax]
    допустимая высадка = пересечение с T

Для выбранных точных S и t:
    возможный возраст = [t − S − Gmax, t − S − Gmin]
```

Первое окно означает существование сочетания условий, а не обещание готовности
при любом прорастании. Второе устойчиво только в рамках заданных G/A и допускает
выбор даты высадки внутри T после всходов. Это не гарантия реальной погоды/развития.
По умолчанию выделять второе окно внутри первого; сохранять и объяснять оба.
Для фиксированной T=20.05.2027, G=5–10, A=50–60:
возможное окно 11–26.03.2027, устойчивое 16–21.03.2027.

Не использовать GrowingSeason как возраст рассады. Не добавлять автоматически
время адаптации после пикировки: новый такой параметр потребует отдельного решения.

## Этапы

При конкретном посеве S ожидаемые всходы [S+Gmin,S+Gmax].
Пикировка [S+Gmin+Pmin,S+Gmax+Pmax]; при неизвестной необходимости — MissingInput,
при явном отключении — None. Закаливание при длительности H:
[Tmin−H,Tmax−H] — окно начала, а не длительность самой операции.
Для выбранной точной высадки t начало закаливания равно t−H.
Показать конфликт, если этап выходит за допустимый порядок событий; не обрезать
его к посеву/высадке и не добавлять лишние дни к возрасту молча.

```text
Calculate(input, profile):
    RequireComplete(G, A, T)
    possible = CheckedWindow(T.start-G.max-A.max, T.end-G.min-A.min)
    resilient = OptionalWindow(T.start-G.min-A.max, T.end-G.max-A.min)
    return Schedule(possible, resilient,
        quantities=CalculateQuantity(input.QuantityMode, profile),
        diagnostics=CheckStageOrder(profile, input.ManualDates))

EvaluateCandidate(sowingDate, transplantWindow, G, A):
    germination = CheckedWindow(sowingDate+G.min, sowingDate+G.max)
    possibleReadiness = [germination.start+A.min, germination.end+A.max]
    overlap = Intersect(possibleReadiness, transplantWindow)
    return Candidate(germination, possibleReadiness, overlap,
        outsideRequestedWindow=overlap.IsNone,
        ageAtRequestedTransplant=EvaluateAgeBounds(sowingDate, transplantWindow, G))
```

## Дополнение: прямой посев и прогноз зрелости

Для DirectSow пользователь задаёт интервал посева S напрямую. Не рассчитывать
его обратным вычитанием возраста 0 из фиктивной даты высадки.
Окно всходов: [Smin+Gmin,Smax+Gmax]. Пикировка/закаливание/высадка неприменимы.
При выборе точного s всходы сужаются до [s+Gmin,s+Gmax].

Вегетация V считается от всходов. Зрелость: [Smin+Gmin+Vmin,Smax+Gmax+Vmax].
Для окон складывать минимальные границы с минимальными, максимальные с максимальными.
Отсутствующий V даёт недоступность прогноза, не произвольное прибавление дней.
Предсказанная зрелость не считается зарегистрированным первым сбором.

```text
CalculateDirectSchedule(S, profile):
    RequireComplete(S, G)
    emergence = CheckedWindow(S.start+G.min, S.end+G.max)
    maturity = profile.Vegetation.Match(v => ShiftWindow(emergence, v.Days),
        () => Unavailable("Не задан срок вегетации от всходов"))
    return Schedule(sowing=S, emergence, maturity,
        transplant=None, pricking=None, hardening=None)
```

Тесты: оба способа при одной культуре; прямой посев без Age; независимые условия;
один учёт G в зрелости; отсутствие V не блокирует посев; нет дат рассады в результате.

## Количество семян и растений

Автоматический режим: N — целевые растения, p — всхожесть, q — потери рассады.
`ceil(N / ((p/100) × (1−q/100)))`. Для N=20,p=80,q=10 результат 28.
Сначала decimal-расчёт, затем проверка верхнего предела, затем перевод в целое.
100% потерь и 0% всхожести — отказ расчёта, не деление на ноль.
Ручной режим сохраняет введённые семена без перезаписи формулой; при известных
процентах отдельно показывает ожидаемый результат и возможный недостаток.
Проценты не являются гарантией результата. Резерв сверх введённых потерь не добавлять.

```text
CalculateQuantity(mode):
    match mode:
        Automatic(N, p, q) => Validate(N,p,q).Bind(values =>
            CheckedInt(Ceiling(N / (p/100m * (1m-q/100m)))))
        Manual(N, seeds, optionalRates) => ValidatePositive(N,seeds)
            .Map(values => Quantity(seeds, Estimate(optionalRates), Manual))
```

## Последовательность, тесты и готовность

1. Red/Green для приведённого примера и точечных G/A/T.
2. Широкая неопределённость, пустое устойчивое окно, пересечение на одном дне.
3. Проверки смыслов: G не учитывается дважды; H/P не удлиняют возраст.
4. Переход года, високосный день, границы DateOnly, отсутствующие/частичные данные.
5. Ручная дата вне окна возвращает диагностику, но не ломает предварительный расчёт.
6. Проценты 100/0, дробные проценты, границы int, ручной режим, пример 28 семян.
7. Исходный профиль/план не меняется, повторный вызов даёт равный результат.

Гейт: `dotnet test Tests/Models.Tests/Models.Tests.csproj`.
Готовность: все окна имеют объяснимый смысл, нет скрытых средних значений,
нулевых подстановок и недоказанных обещаний готовности рассады.

## Ориентир по округлённым средним

Подтверждён как дополнительное представление, не замена окон:

```text
meanG = Ceiling((Gmin + Gmax) / 2m)
meanA = Ceiling((Amin + Amax) / 2m)
meanSowing = [Tmin - meanG - meanA, Tmax - meanG - meanA]
```

Каждое среднее округляется отдельно вверх, затем значения складываются;
использовать расширенный численный тип и проверку переполнения. Например,
G=10–15, A=65–70 → 13+68=81 день; T=25–30.05.2022 → 05–10.03.2022.
У DirectSow посев задан вручную: показывать средний ориентир всходов S+meanG,
не создавать обратный расчёт через возраст 0. Тестировать отдельное округление
двух полуцелых средних, отсутствие данных и оба режима выращивания.
Периоды цветения/плодоношения и межсезонные расчёты — по этапу 11.
