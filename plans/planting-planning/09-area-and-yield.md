# Этап 9. Вместимость грядки и прогноз от желаемого урожая

Статус: реализовано, гейт 1722/1722. [Общий план](README.md).

## Реализация и проверка

BedLayout хранит десятичные метры и четыре отступа относительно рядов.
BedCapacity считает целые позиции; 5/6 мест для примера подтверждены тестами.
HarvestProjection даёт оба прогноза, обратную потребность, нехватку мест/площади.
Режимы количества — вручную, вместимость, цель по растению, цель по м².
Площадь урожая задаётся явно. Потребность не ограничивается вместимостью.
Seeds рассчитываются существующим SeedQuantityCalculation для новой потребности.

Нормы культуры/сорта независимы; миграция AddPlanningYieldNorms добавляет только
nullable колонки, Down их удаляет. Прежнее YieldKg не используется как новая норма.
Приоритет сорт → культура разрешается отдельно для каждой нормы, источник сохранён.
Снимок Harvest в прежнем JSON необязателен; чтение старого формата проверено.
Грядки читаются свежей проекцией без EF-графа; CanvasGeometryMapper переводит
размеры по CanvasConstants, без zoom/округлённой строки. Это копирование снимка,
не живая связь. После ручного изменения размеров подпись источника очищается.
Схема сорта в сантиметрах переносится только явной командой; отступы редактируемы.

TDD: 5 чистых случаев, Application цели/семян/наследования, SQLite round-trip
снимка и fresh-чтение Bed без изменения сетки. WPF: неверный ввод, раскрытый
редактор, активные привязки и просмотр PNG при 100/150%. Полный гейт 1722/1722.
Сезонные прогнозы суммируются по уникальным ID отдельно для двух норм;
неизвестные прогнозы подсчитываются, переполнение показывается явно.
Совместимость нескольких партий на общей грядке явно не обещается.
Зависимости: 1–3, 5–7; контракт до миграций 5, итоговый гейт после этапов 9–11.

## Цель и файлы

Рассчитать размещаемое число растений по длине/ширине грядки и схеме, прогноз
урожая и потребность в растениях/семенах от желаемого количества кг.
Нормы поддерживаются одновременно в кг/растение и кг/м². Журнал — этап 10.
Новые Domain-типы: BedDimensions, BedLayout, YieldStandards, YieldTarget,
BedCapacity, HarvestProjection в `Bonfire.Domain/Planning/`.
Application/DB: независимое чтение размеров Bed, расширение preview и снимка партии.
WPF: размеры/ориентация рядов/отступы, нормы, цель урожая, потребность и дефицит.
Проверки: BedCapacityTests, YieldProjectionTests, PlanningStorageTests и WPF.

## Вход и границы

- Размеры прямоугольника в метрах: снимок выбранной грядки либо ручные значения.
  При чтении Bed использовать фактический общий mapper/CanvasConstants,
  не умножать UI zoom на метры и не округлять через отображаемую строку конвертера.
- Схема LandingPattern/LandingRowSpacing переиспользуется после проверки смысла
  расстояний между растениями и рядами. Неполная/нулевая схема не даёт вместимость.
- Ряды вдоль длины/ширины, четыре отступа в метрах — явные поля.
- Проектная начальная схема: отступ половины соответствующего шага. Пользователь
  ещё не выбирал это правило; показывать его и допускать изменение перед расчётом.
- Отступы могут быть 0, но размеры/шаг положительны. Только конечные значения.
- Шахматная посадка, сложные формы и автоматическое заполнение ячеек не входят.
- Для контейнера при желании расчёта размеры задаются вручную по той же модели;
  это не фиктивная грядка в БД. Ручное количество всегда доступно без геометрии.

## Вместимость и псевдокод

```text
CountPositions(size, before, after, step):
    Require(size > 0, before >= 0, after >= 0, step > 0)
    span = size - before - after
    if span < 0: return 0
    return CheckedInt(Floor(span / step) + 1)

CalculateBed(layout):
    along, across, plantStep, rowStep = Orient(layout)
    perRow = CountPositions(along, startMargin, endMargin, plantStep)
    rows = CountPositions(across, leftMargin, rightMargin, rowStep)
    capacity = CheckedMultiply(perRow, rows)
    return Capacity(rows, perRow, capacity,
        grossArea=length*width, theoreticalDensity=1/(plantStep*rowStep))
```

Пример: 2×0,9 м, шаг растений 0,4 м, рядов 0,6 м, отступы по половине шага.
Вдоль длины: 5 растений × 1 ряд = 5. После смены направления: 2 × 3 = 6.
Отношение площади к площади питания даёт 7,5 и не считается вместимостью.
Предложения двух ориентаций можно сравнить; направление не менять незаметно.
Сохранять размеры/раскладку снимком; изменение реальной грядки требует явного
пересчёта плана и не меняет фактическую геометрию/сетку.
При использовании одной грядки несколькими партиями нельзя обещать их совместное
размещение, суммируя отдельные максимумы. Проектное решение: рассчитывать заданный
для партии прямоугольник внутри грядки с явными размерами; размещение общих
участков требует непересечения либо явной диагностики «совместимость не проверена».

## Урожайность, прямой и обратный расчёт

Нормы независимы: исходное кг/растение не перезаписывать вычисленным кг/м².
Если заполнена только одна норма, вторую можно показать как расчётный эквивалент
с указанием плотности; не сохранять её как независимую заявленную норму.
Если заполнены обе и они дают разные прогнозы, показать оба и дать явно выбрать
норму для цели. Старое YieldKg сохраняется до подтверждения его базы.

Для нормы на м² пользователь видит расчётную площадь урожая. Предлагаемая база —
площадь, выделенная партии, с явно обозначенными проходами/неиспользуемой частью;
не выводить её молча из округлённого количества. Выбор базы хранится в снимке.

```text
Forecast(N, ratePerPlant, ratePerM2, yieldArea):
    perPlantProjection = ratePerPlant.Map(rate => N*rate)
    perM2Projection = ratePerM2.Map(rate => yieldArea*rate)
    return BothWithSources(perPlantProjection, perM2Projection)

PlanForTarget(targetKg, selectedRate, layout, germination, loss):
    Require(targetKg > 0, selectedRate > 0)
    capacity = CalculateBed(layout)
    if selectedRate is PerPlant(rate):
        requiredPlants = Ceiling(targetKg/rate)
    else:
        requiredArea = targetKg/selectedRate.KgPerM2
        equivalentPerPlant = selectedRate.KgPerM2 * plantStep*rowStep
        requiredPlants = Ceiling(targetKg/equivalentPerPlant)
        // эквивалент — оценка по плотности, явно помеченная в UI
    seeds = Ceiling(requiredPlants/(germination*(1-loss)))
    return TargetPlan(requiredPlants, seeds, requiredArea,
        capacity, deficit=Max(0, requiredPlants-capacity),
        areaDeficit=CompareRequiredAndAllocatedAreaIfApplicable())
```

Нехватка места не уменьшает потребность автоматически. Отдельно показать цель,
необходимые растения/площадь, вместимость, возможный урожай и дефицит. При норме
на м² проверять и требуемую площадь, и геометрическую вместимость; расчётный
эквивалент на растение не доказывает агрономическую норму или достижение урожая.
Нулевая норма допустима как справочное значение, но запрещает обратное деление.

## Последовательность, проверки и готовность

1. Red/Green для рядов, отступов и обеих ориентаций; независимое чтение размеров.
2. Нормы в кг, указание базы прежнего YieldKg, независимость двух норм.
3. Red/Green: цель урожая, округление растений/семян вверх, дефицит, нулевая норма.
4. Снимок размеров/раскладки/норм/цели с партией — один SaveChanges, DTO без EF.
5. UI: ручной режим, от грядки, от цели урожая; нет тихой смены режима и ввода.
6. Сезонный итог только по уникальным ID партий; недоступные прогнозы видны.
7. Тесты на размер меньше отступов, точное попадание, нулевые поля, переполнение,
   изменение грядки после сохранения, общий Bed у нескольких партий.
8. Проверить, что сохранение плана не резервирует/не создаёт ячейки и не списывает семена.

Гейт: Models.Tests + Services.Tests (SQLite) + ViewModels.Tests, затем этап 8.
Готовность: вместимость рассчитана по рядам и размерам, цель не подменяется
возможностями грядки, нормы имеют единицы/базу и отличимы от фактического журнала.
