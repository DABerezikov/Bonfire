# Этап 7. WPF: библиотеки, партии и просмотр сроков

Статус: план. Зависимость: [этап 6](06-application.md). [Общий план](README.md).

## Цель и файлы

Дать пользователю редактируемые справочники, сезонный список партий, понятный
просмотр сроков, конфликтов и ручного выбора. Не привязывать редактор к EF.

Новые: `Bonfire/Views/Planning/PlantingPlanningView.xaml`,
`PlannedBatchEditor.xaml`, `RegionEditor.xaml`, `GrowingProfileEditor.xaml`,
`Bonfire/ViewModels/PlantingPlanningViewModel.cs`,
`Bonfire/Models/Planning/PlannedBatchEditorDraft.cs` и модели библиотек.
Изменить: `Bonfire/ViewModels/LibraryEditorViewModel.cs`, ViewModelRegister,
`Bonfire/Views/Windows/MainWindow.xaml`, MainWindowViewModel и фактический XAML
редактора библиотек после уточнения существующей навигации.
Проверки: `Tests/ViewModels.Tests/PlanningWorkflowTests.cs`,
`PlanningEditorWpfTests.cs`, при необходимости `Tests/Models.Tests/`.

## Поток пользователя

1. В библиотеках: регион с зоной/заморозками; культура с агропрофилем;
   таблица региональных сроков с отдельными строками «Грунт» и «Теплица».
2. Открыть/создать сезонный план, выбрать регион и сорт через культуру.
3. Добавить партию: условия высадки, ручной интервал, целевые растения,
   автоматический/ручной режим семян, параметры наследования.
4. Рядом постоянно показывать справочные сроки для обоих условий и источник.
   Кнопка «Использовать интервал» явно копирует справку в ввод.
5. «Рассчитать»: окна посева/всходов/пикировки/начала закаливания/высадки,
   число семян, происхождение параметров, подходящие лунные дни.
6. При конфликте: исходное окно, ближайшие варианты раньше/позже, сдвиг в днях,
   изменение возраста, ручная дата. Выбор предложения не сохраняет план автоматически.
7. «Сохранить»/«Отменить»; после сохранения партия видна в сезонном списке.
   Несколько партий сорта остаются отдельными строками, с собственной нумерацией.

Первое представление — список партий и шкала/таблица этапов; сложный drag-and-drop
календарь не является условием готовности. Не показывать технические имена типов,
версий и Fingerprint в обычном пользовательском потоке.

## Черновик и асинхронность

Дополнение к экрану: явный выбор «Через рассаду» / «Прямой посев». У первого
редактируется интервал высадки, у второго — интервал посева. Для прямого посева
скрываются неприменимые возраст/пикировка/закаливание/высадка, показываются всходы
и прогноз зрелости. Переключение режима инвалидирует preview; несохранённые поля
не уничтожаются молча. Нельзя назвать плановые даты фактическими или выводить
их как события существующего журнала рассады. План/факт из Excel пока не переносится.

Черновик содержит независимые InputValues и OriginalSnapshot, ручные даты,
версию и текущий preview. Dirty сравнивается со снимком, не с живым кэшем.
Nullable допускается на границе DatePicker; маппер передаёт Option/проверенные даты.
Числовые ошибки WPF блокируют сохранение, не превращаются в ноль.
Значение 0% потерь допустимо; пустая строка означает отсутствие, а не 0%.

```text
OnCalculate():
    capturedDraft = EditedItem
    input = CaptureValidInput(capturedDraft)
    revision = capturedDraft.Revision
    preview = await planningService.CalculateAsync(input)
    if EditedItem == capturedDraft && capturedDraft.Revision == revision:
        capturedDraft.ApplyPreview(preview)

OnSave():
    capturedModel, capturedDraft = SelectedBatch, EditedItem
    submittedValues = capturedDraft.Values
    result = await planningService.SaveAsync(submittedValues, capturedDraft.Version)
    result.Match(receipt => {
        UpdateCapturedCache(capturedModel, receipt)
        if EditedItem == capturedDraft:
            AcceptSavedSnapshotPreservingLaterInput(capturedDraft, submittedValues, receipt)
    }, error => ShowErrorKeepingDraft(error))

OnCancel():
    EditedItem = CreateIndependentDraft(SelectedBatch.CachedSnapshot)
    ClearEditorValidationErrors()
```

После позднего сохранения новый выбор не меняется. Последующий ввод пользователя
сохраняется относительно принятого снимка через общий WithChangeFrom там, где
он применим. Для расчёта и сохранения использовать LambdaCommandAsync с защитой
от повторного запуска; старые ответы чтения игнорируются.
При удалении захватить запись/коллекцию до await; отказ сохраняет выбор и черновик.

## Проверки и критерии готовности

- Red/Green: независимость черновика, смена выбора при await, поздний ввод,
  отмена, отказ записи, повторное нажатие, устаревший preview.
- STA/WPF: неверные числа и даты не сохраняются, ошибки снимаются отменой;
  ручные значения не пропадают после расчёта и смены справки.
- Проверить две партии, оба условия, отсутствие профиля, проценты и лунный конфликт.
- Визуально: обычный размер окна, масштаб Windows 100/150%, длинные имена/сообщения,
  клавиатурная навигация, отсутствие горизонтального обрезания и binding errors.
- Источник региональной справки доступен пользователю; факт заморозка не выдаётся
  за прогноз, ручной выбор явно различим с рекомендацией.

Гейт: `dotnet build Bonfire.sln`, ViewModels.Tests и визуальный smoke нового экрана.
Готовность: весь согласованный сценарий выполняется в UI с сохранением и повторным
открытием; нет прямого EF, тихой коррекции ввода или потери поздних изменений.

## Уточнения представления после ответов владельца

Цвета, «п», «?» и четыре деления месяца Excel не являются макетом или статусами.
UI строится под сценарии Bonfire. Показывать окна и отдельный ориентир по средним;
температура почвы — только справка. Добавить подоконник/контейнер без микрозелени.
Не добавлять повторные волны и их генерацию. Вместимость грядки/цель урожая —
по этапу 9; журнал сборов — по этапу 10; многолетние посадки/периоды — по этапу 11.
Ручной журнал явно отделён от прогнозов и существующего журнала рассады.
