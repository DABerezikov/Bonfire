# Этап 10. Ручной журнал сборов урожая

Статус: реализовано, гейт 1735/1735. [Общий план](README.md).

## Реализация

HarvestEntry/HarvestMass/HarvestIdentity и HarvestSummary — независимый Domain.
ManageHarvestJournal проверяет локальный день региона через TimeProvider,
сохраняет/исправляет/удаляет через порты. Фасад HarvestService не зависит от EF.
DbHarvestJournal читает свежую запись, проверяет версию и пишет одним SaveChanges.
Редактируются дата, масса и примечание; принадлежность существующего сбора
остаётся прежней, включая снимки имён и сезона. None и Some("") различаются.

Новая таблица HarvestJournalEntries не связана с фактическими Seed/Seedling/Spot.
Живые FK партии/культуры/сорта — SetNull; отдельные исторические ID/имена остаются.
Удаление плана и библиотечных строк не удаляет факты и не запрещает их исправлять.
Миграция AddHarvestJournal имеет Down. Контракт PerennialPlantingId подготовлен;
чтение и выбор многолетнего источника подключаются этапом 11.

Экран «Сборы урожая» доступен в меню: ручной ввод без партии либо выбор партии
заданного сезона, фильтры сезона/культуры/сорта/ID партии, итог и первый сбор.
Сравнение с двумя сохранёнными прогнозами возможно только для той же партии
и области фильтров; без партии/после удаления прогноза сравнение недоступно.
Черновик независим, поздняя масса сохраняется, следующий Save использует полученный
ID и версию. Повторное нажатие защищено. Позднее чтение не стирает результат записи.

TDD: 4 Domain случая, 4 SQLite/Application случая, 3 workflow и 2 STA/WPF масштаба.
Проверены отказ SQLite, версии, SetNull, исправление после удаления библиотеки,
часовой пояс Томска, сохранность 100 реальных семян и неверный текст без обнуления.
Полный гейт: 1735/1735; сборка — 0 ошибок/предупреждений. PNG просмотрены.
Зависимости: 1, 5–7, 9, 11 для многолетних посадок.

## Цель и граница

Пользователь вручную регистрирует отдельные сборы с датой и массой в кг,
видит итог по сорту/партии/сезону и сравнение с сохранённым прогнозом.
Связь с реальными посевами/всходами остаётся отложенной. Сбор не переводит ячейку
в Harvested и не назначает HarvestDate, не уменьшает растения и не меняет семена.

## Файлы и контракты

Новые `Bonfire.Domain/Harvest/`: HarvestEntryId, HarvestMass, HarvestEntry.
Новые `Bonfire.Application/Harvest/`: AddHarvestEntry, EditHarvestEntry,
DeleteHarvestEntry, ReadHarvestJournal, порты и независимые DTO.
DB: `BonfireDB/Entities/Planning/HarvestEntry.cs`, адаптеры `BonfireDB/Harvest/`,
DbBonfire/RepositoryRegister, миграция. WPF: HarvestJournalView.xaml,
HarvestJournalViewModel, независимый черновик, фасад/маппер/DI.
Тесты в Models.Tests, Services.Tests и ViewModels.Tests.

- Масса — положительный decimal в кг с проверкой диапазона. Пустое/0 не запись
  об отсутствии урожая; нулевые сборы не создают ложное событие первого сбора.
- Дата — DateOnly, фактический сбор. Проектное правило: будущая дата не принимается
  как факт; текущий день определяется TimeProvider и зоной региона.
- Запись хранит положительные CultureId/SortId при создании, сезон и снимки имён,
  Option<PlannedBatchId>/Option<PerennialPlantingId> для выбранного объекта.
- Предлагается разрешить запись и без плановой партии: пользователь выбирает
  культуру/сорт. Такая запись не распределяется между партиями автоматически.
- Примечание необязательное, None отличается от Some("").
- ID и версия для редактирования; исправление меняет существующий сбор,
  повторный Save не создаёт дубликат. Ошибка сохраняет черновик.

## Псевдокод

```text
AddHarvest(request):
    today = timeProvider.TodayIn(request.RegionZone)
    entry = HarvestEntry.Create(request.Date, request.MassKg,
        request.Identity, request.Note.ToOption(), today)
    return entry.BindAsync(writer.InsertOnceAsync)

SaveEdit(request):
    fresh = LoadEntry(request.Id)
    CheckExpectedVersion(fresh, request.Version)
    validated = fresh.WithDetails(request.Date, request.MassKg, request.Note)
    ApplyOnlyJournalFields(validated)
    await SaveChangesAsync()
    return IndependentReceipt()

Summarize(entries, filters, savedForecast):
    unique = Filter(entries, filters).DistinctBy(EntryId)
    totalKg = SumChecked(unique.MassKg)
    firstHarvest = unique.MinDateOrNone()
    deviation = savedForecast.Map(predicted => totalKg-predicted)
    return Summary(totalKg, firstHarvest, deviation, unique.Count)
```

Сравнение с прогнозом использует тот же сезон/набор партий. Общую запись без партии
не сравнивать с одной произвольной партией. Нормы фактических кг/растение или кг/м²
считать только при известной базе количества/площади и подписывать её как плановую,
если фактическая численность/площадь не вводилась. Прогноз журнала не переписывает.
«Начало фактического сбора» = минимальная дата положительного сбора, не зрелость.

## Запись, удаление и UI

Одна операция — один SaveChanges. Собирать итоги запросом/чистой функцией,
не дублировать изменяемую сумму в нескольких таблицах. При удалении плановой партии
связь журнала SetNull либо архив, но масса/дата/снимки остаются. Удаление библиотеки
не каскадирует сборы. Проверить совместимость FK с существующими CRUD библиотек.
Удаление самого сбора — явная пользовательская команда, без удаления партии.
UI захватывает исходную запись до await; смена выбора и поздний ввод сохраняются.
Фильтры: сезон, культура, сорт, партия; создание/исправление/удаление и общий итог.
