# Карта контрактов: первый этап

База: `8a51f5f`. Проверено по `Entities`, `DbBonfire`, мапперам, сервисам и команде
создания рассады. Это текущий контракт хранения, а не завершённая доменная модель.

| Владелец | Данные и связи | Правило изменения |
|---|---|---|
| `PlantCulture` | Название, класс | Библиотека; общая культура нескольких растений |
| `Producer` | Название | Библиотека; связан с сортом |
| `PlantSort` | Название, производитель, сроки, высота, цвет, схема, масса плода, урожайность, описание | Характеристики общие для записей сорта; без дублирования в пакете |
| `Plant` | Ссылки на культуру и сорт | Связующая запись; производитель доступен через сорт |
| `Seed` / `SeedsInfo` | Растение, упаковка, источник, даты, цена, остатки, примечание и причина удаления | Остатки в штуках и граммах хранятся отдельно |
| `Seedling` | Растение, SeedId, посеяно, вес, высажено, метаданные партии | Посев создаёт партию и списывает выбранную единицу атомарно |
| `SeedlingInfo` | Посев/всход, карантин, закаливание, гибель, пересадки и обработки | Черновик не разделяет изменяемые вложенные объекты с оригиналом |
| `GardenPlan` / `GardenPlot` | План, участки, вложенные теплицы | Сохраняется Composite и существующие DB-дискриминаторы |
| `GardenElement` / `PlantingSpot` | Геометрия, состояния, размещение и ссылка на рассаду | Сохраняются полиморфные переходы; посадка через `PlantingService` уже атомарна |

## Посев: подтверждённая семантика

- Источник команды — конкретный пакет, а не строковое имя сорта/производителя.
- Единица выбирается текущим UI: положительный вес → граммы, иначе штуки.
- Отсутствующий вес (`AmountSeedsWeight == null`) не означает нулевой известный вес:
  для посева в граммах это отсутствие данных, операция должна вернуть отказ.
- Количество хранится как `double`, включая штуки. Ограничение целыми числами
  потребует отдельного согласования; на этом этапе его не вводим.
- Для расчёта нужны конечные неотрицательные остатки и конечный положительный расход.
  Превышение доступного остатка возвращает отказ, а не отрицательный остаток.
- Проверка и расчёт выполняются по свежей записи из БД. UI-кэш обновляется после успеха.
- Метаданные партии и запись номер 0 сохраняют одинаковые дату, фазу, источник и место.

## Явное отсутствие и последующие решения

В новых доменных операциях нет nullable-результата: ожидаемый отказ представлен
существующим `Result`, успех обрабатывается через `Match`/`Bind`. Общий `Result`
постепенно переносится в независимый слой; его старые nullable-accessors остаются
совместимостью для неперенесённых сценариев, а не рекомендуемым новым контрактом.

Необязательные даты и характеристики пока остаются nullable на EF/WPF-границе.
Следующие этапы должны определить семантику каждого поля перед переходом на `Option`.
Отдельные открытые вопросы: различие пустой строки и отсутствия в текстах, диапазоны
неполных характеристик, владение связью культура–сорт при совместном использовании.
Схему, DB ID, названия столбцов и исторические данные на этом этапе не меняем.
