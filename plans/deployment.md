# Развёртывание на MONOBLOCK

Цель: push в основную ветку `master` → полный тест-гейт и self-contained публикация
на Windows GitHub → установка через интерактивный runner с подтверждением пользователя.

## Последовательность

1. Скрипт бэкапа/обновления и установщик runner — коммит `3d591bd`.
2. Подтверждение в XAML, штатное закрытие без kill, тесты и workflow.
3. Полный локальный гейт, merge в `master`, push без force.
4. Проверка настоящего workflow: build и job на MONOBLOCK, результат подтверждения,
   резервная копия, версия установленного приложения. При отказе это отмена
   установки, а не успешное развёртывание.

## Контракт

- Установка сохраняет БД/SQLite sidecars, настройки и отчёты. Приложение после
  обновления автоматически не запускается; миграции при ручном запуске прежние.
- Старые файлы сначала копируются в `backups`, SHA-256 проверяется до замены.
- Отказ/тайм-аут диалога не закрывают приложение и не меняют установку.
- Runner — `MONOBLOCK-Bonfire`, online проверен через GitHub API; запуск при входе
  текущего пользователя, а не служба. Нет сеанса — обновление невозможно.
- Сборка проходит на GitHub, на MONOBLOCK SDK не требуется. Для job используются
  метки `self-hosted`, `Windows`, `X64`, `bonfire-monoblock`, `interactive`.
- `concurrency` сериализует workflow, файловая блокировка защищает установку.
- Успех записывает commit и путь бэкапа в `.bonfire-version.json`.

## Доказательства

До workflow: 9 проверок deploy, 12 runner, общий гейт 1538/1538.
Интерактивное обновление: 6 сценариев Red → Green; XAML и тайм-аут проверяются
отдельным STA smoke. Итог реального прогона фиксируется после push.

Локальная проверка перед push: 1538/1538, 27 сценариев PowerShell, настоящий
XAML render и отказ по тайм-ауту успешны. PNG: `artifacts/update-dialog/confirmation.png`.
SDK на MONOBLOCK не устанавливался; его runner подтверждён online/free через API.

Первый GitHub run `41074819235` выявил зависимость конструктора SeedsViewModel от
русской культуры и теста добавления теплицы от экрана 1920 DIPs. До установки
прогон не дошёл. Дата заменена на конструктор DateTime (en-US/ar-SA сначала
доказаны падающими тестами); ожидание размеров использует штатный CanvasConstants.

Второй run `41075787535`: конструктор и масштаб исправлены; остались два сценария
добавления, где дата повторно разбиралась строкой при очистке формы. Этот вызов
также заменён конструктором; сценарии пополнения и нового пакета теперь отдельно
проверяются при ru-RU/en-US/ar-SA (Red: 4 отказа и 2 успеха).

Третий run `41076826202`: облачный build полностью зелёный, 1545/1545 и проверки
скриптов/startup пройдены. На MONOBLOCK checkout успешен; inline PowerShell в YAML
не разобрался из-за UTF-8 без BOM при ANSI CP1251. Русские сообщения перенесены в
PS1 с BOM; разбор всех inline-команд при CP1251/CP1252 проверен Red → Green.

## Итог реального прогона 30.10.2026

[Run 41078147864](https://github.com/DABerezikov/Bonfire/actions/runs/41078147864),
commit `0aa83b2`: build успешен, **1545/1545**, 27 сценариев PowerShell,
проверка кодировок, настоящий XAML и startup/exit smoke зелёные.
MONOBLOCK принял job, выполнил checkout и проверку компьютера. Артефакт
74 518 599 байт скачан и проверен по SHA-256; передача заняла около 10,5 минут.

Шаг подтверждения ожидал 5 минут и завершился отказом по отсутствию ответа
(сообщение в журнале: пользователь отложил обновление или не ответил).
Закрытие приложения, резервное копирование и замена файлов не выполнялись.
До и после прогона совпали SHA-256 `BonfireDB.db`, `appsettings.json`, `Bonfire.exe`;
маркера новой версии нет. Сам факт установки с подтверждением ещё не проверен.

Для продолжения нужен пользователь у MONOBLOCK, готовый подтвердить окно.
GitHub Actions позволяет повторить failed job этого прогона, сохранив успешный
build; повторная загрузка артефакта может занять заметное время. Повторный запуск
без ответа пользователя не выполнялся. Приложение автоматически не запускалось,
БД не открывалась приложением и миграции не применялись.
