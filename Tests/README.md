## Запуск и покрытие

Нужны Windows и .NET SDK из `global.json`. Тест-гейт — все пять проектов:

```powershell
dotnet test Bonfire.sln
dotnet test Tests/ViewModels.Tests/ViewModels.Tests.csproj --filter "FullyQualifiedName~GardenPlanWorkflowTests"
dotnet test Bonfire.sln --settings Tests/coverage.runsettings --collect:"XPlat Code Coverage" --results-directory artifacts/coverage-new
python Tests/summarize_coverage.py artifacts/coverage-new --output artifacts/coverage-new.md
```

Для сравнения с локальным исходным замером добавьте `--baseline artifacts/coverage-baseline`.
Каждый новый замер сохраняйте в отдельный каталог: объединение старых и новых запусков
может скрыть регрессию. XML и TRX остаются в игнорируемом `artifacts/`.
Зафиксированный результат — [COVERAGE.md](COVERAGE.md). Скрипт объединяет строки
всех проектов по исходным путям; проценты разных проектов не усредняются.
Миграции и сгенерированный код исключены из числовой метрики, но миграции проверяются
отдельными SQLite-тестами. Покрытие строк не означает полного покрытия ветвей или UI.

## Изоляция и ограничения

- SQLite-тесты используют БД в памяти; рабочая `BonfireDB.db` не открывается.
- Excel-тесты используют уникальный временный каталог, восстанавливают текущий каталог
  и настройки EPPlus. Коллекция не выполняется параллельно с другими тестами.
- WPF-тесты создают один обычный `Application` на отдельном STA-потоке,
  загружают настоящие ресурсы и обрабатывают события. `Bonfire.App.OnStartup`,
  настоящий главный экран и модальные диалоги не запускаются.
- Ожидаемые числа лунного календаря фиксируют текущий алгоритм; они не доказывают
  астрономическую точность.
- Нативные OpenFile/SaveFile, MessageBox, диалог причины удаления, реальное завершение
  приложения, обработчики глобальных ошибок и полный startup требуют отдельного
  интерактивного/процессного UI-гейта. Они не объявляются автоматически покрытыми.
- Для нескольких разрешений и DPI остаётся визуальная проверка. Автотесты проверяют
  расчёты и ограничения относительно текущего масштаба экрана.

## Риски для следующего этапа

Первая часть этапа библиотек проверяется в `CultureDefinitionTests`,
`CultureApplicationTests`, `CultureEditingIntegrationTests`: инварианты, новое
состояние без изменения оригинала, связанные семена/рассада и отказ SQLite.
Общий гейт после переноса культуры — 724/724. Остальные операции библиотек и пакета
семян остаются следующими частями рефакторинга.

После этапа DI/startup общий гейт составляет 701/701. `ApplicationLifetimeTests`,
`WindowShutdownTests`, `WindowShutdownWpfTests` и `ApplicationStartupIntegrationTests`
проверяют порядок, отмену и освобождение. Настоящий WPF smoke запускается отдельно:
`dotnet run --project Tests/Startup.Smoke/Startup.Smoke.csproj`. Утилита не является
шестым xUnit-проектом и не входит в обычный `dotnet test Bonfire.sln`; она создаёт
отдельную БД в своём `bin/`, использует невидимое окно и проверяет его загрузку,
закрытие и освобождение host. Это проверка успешного процесса, а не автоматизация
нативных ошибок, диалогов подтверждения или завершения Windows.

После выделения Application сценарий посева проверяется также в `SowingApplicationTests`;
явное отсутствие — в `OptionTests`, SQLite-контракт — в `SowingIntegrationTests`.
Текущий итог после второго этапа: 684/684; показатели покрытия выше относятся к базе
перед рефакторингом. Последовательность и результаты — в журнале реализации.

Этот список зафиксирован до рефакторинга. В первой реализации устранены совместное
владение коллекциями черновика и раздельное сохранение посева; новые проверки и
оставшиеся ограничения описаны в [журнале](../plans/refactoring-progress.md).

- `SeedlingMapper.CopyInto` присваивает ту же коллекцию `SeedlingInfos`: черновик
  разделяет метаданные с исходной записью. Без отдельного решения нельзя считать
  отмену таких изменений полноценным откатом; правильную изоляцию следует задавать
  новым Red-тестом, а не закреплять разделение коллекции как требование.
- `DbInitializer` зарегистрирован singleton, хотя получает scoped `DbBonfire`.
  Текущий smoke-тест проверяет действующую сборку зависимостей; он не утверждает,
  что lifetimes корректны при строгой проверке областей.
- Посев из окна рассады сохраняет партию и остаток семян отдельными вызовами.
  Согласованность при отказе между ними требует отдельного транзакционного контракта.

Эти риски отмечены для архитектурного этапа; производственные исправления в текущую
работу не включены. Не заменяйте проверки реального поведения assertions по числу
вызовов только ради роста процента покрытия.
