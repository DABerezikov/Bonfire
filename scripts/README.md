# Развёртывание Bonfire

Запускайте из корня репозитория в Windows PowerShell 5.1 или PowerShell 7.
Для сборки нужен .NET SDK из `global.json`, для записи — доступ к сетевой папке.
Закройте Bonfire на всех компьютерах, использующих эту установку.

```powershell
# Предварительный просмотр без сборки и записи
.\scripts\Deploy-Bonfire.ps1 -WhatIf

# Release, win-x64, self-contained; затем установка в \\MONOBLOCK\Bonfire
.\scripts\Deploy-Bonfire.ps1

# Установка из заранее подготовленного dotnet publish
.\scripts\Deploy-Bonfire.ps1 -PublishDirectory .\artifacts\my-publish
```

Скрипт сначала публикует приложение в уникальный локальный каталог
`artifacts/deploy-publish/`, затем сохраняет прежние файлы в
`\\MONOBLOCK\Bonfire\backups\yyyyMMdd-HHmmss-fff-<id>\`.
В бэкап входят БД, настройки и отчёты; прежние бэкапы не копируются повторно.
Каждый файл проверяется по SHA-256. Маркер `.backup-complete` означает, что копия
завершена; без него каталог считается незавершённым. Только после этого
заменяются файлы публикации. Старые файлы, отсутствующие в публикации, сохраняются.

Файлы `*.db`, `*.db3`, `*.sqlite`, `*.sqlite3` и их `-wal`, `-shm`, `-journal`
не устанавливаются из публикации и не изменяются. На время копирования они
открываются с запретом записи. Существующие `appsettings*.json`, `*.config`,
каталоги `Reports`, `Logs`, `backups` сохраняются. При первой установке настройки
копируются, БД из публикации — никогда. Приложение скрипт не запускает;
штатные миграции при последующем запуске приложения остаются прежними.

При ошибке замены скрипт пытается восстановить уже затронутые файлы из бэкапа.
При потере сети или питания автоматическое восстановление не гарантируется:
закройте приложение и восстановите файлы из последней завершённой копии.
БД при откате версии вручную не заменяйте. Бэкапы автоматически не удаляются.
При аварийном завершении может остаться `.bonfire-deploy.lock`; удаляйте его
только убедившись, что другое развёртывание не выполняется.

Проверки на изолированных локальных файлах, без обращения к MONOBLOCK:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File Tests/Deployment/Deploy.Tests.ps1
dotnet test Bonfire.sln
```

Для непрерывного развёртывания используйте Windows runner с доступом к ресурсу:
тесты → публикация → этот скрипт. Запуски необходимо сериализовать; приложение
должно быть закрыто. Облачный runner сам по себе не имеет доступа к локальной
сети. Учётную запись runner настройте с правами на ресурс, без паролей в скрипте.

Проверено: 9 сценариев скрипта, общий гейт 1538/1538, реальная self-contained
Release-публикация и установка 459 файлов в изолированную локальную папку.
Развёртывание на MONOBLOCK и работа через SMB пока не проверялись.

Установка GitHub runner с запуском при входе пользователя на MONOBLOCK:
[Install-BonfireRunner.md](Install-BonfireRunner.md).
